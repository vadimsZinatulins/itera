# 22: Suggest relevant open threads

**What to build:** Give the learner low-typing starting points for useful conversations, with clear reasons based on approved material and reviewed uncertainty rather than assumed mastery.

**Blocked by:** 09 — Review incremental recaps into Subject understanding.

**Status:** ready-for-agent

- [ ] Show suggested open threads in the new-chat experience and keep the entry reachable while a conversation is selected, following the accepted seamless trail direction.
- [ ] Give each suggestion an understandable short reason and allow another topic or a free-form request. Suggestions do not override the learner's current request or substitute canned answers for reasoning.
- [ ] Ground subject content in current eligible approved material and learning interpretation in reviewed observations. Tentative conversation activity may be visible but cannot become an unreviewed ability judgment.
- [ ] Starting a suggested thread uses the existing conversation flow, account/Subject scope and durable identity rules. Do not require a separate Start ceremony or create duplicate threads on retry.
- [ ] Handle missing approved sources honestly with a route to author/approve material rather than fabricated practice topics. Reflect current source/observation changes when suggestions are next requested rather than using removed material.
- [ ] Keep generation bounded to initiated workflows; no scheduled analysis or automatic whole-history reprocessing. Avoid hard-coding the prototype's exact two suggestions or sample curricula as production rules.
- [ ] Preserve separation from assessment: a suggestion can lead to an ordinary exploration, while any assessment uses its existing entry and review rules.
- [ ] Public-boundary tests cover reasons, alternate/free-form entry, initial/existing chat access, approved/reviewed context boundaries, empty sources, changed observations, account isolation and no duplicate conversation creation using controlled provider responses.
